> 环境：Windows，Node.js v22.22.2（managed），无第三方依赖的纯逻辑模块 + `modbus-serial` 模拟器。

## 二、关键测试结果

### 1. 单元测试套件：50 PASS / 1 FAIL

唯一失败用例即 Q2 对应的阶跃告警时延：

```
FAIL  阶跃告警时延代价不超过 2 s   legacy=0 ms, v2=98000 ms
```

- **含义**：温度 25→85 ℃ 阶跃、阈值 80 ℃，纯阈值判据（legacy）0 ms 报警，而本文告警引擎（v2）延迟 98 s 才报警。
- **性质**：真实功能缺陷，非测试误判。根因见 `01_专家评审意见与质疑.md` 的 Q2。

### 2. PLC 模拟器端到端链路

```
[主包] 寄存器 = 834, 2504, 455, 193, 23
       温度=83.4°C 压力=250.4kPa 湿度=45.5% 序号=23 扩展协议=true 异常位图=1
[子包] 子包序号=23 位图=1 异常值= {temperature:83.4, ...}
[写回] 已写 2021=1000（100.0kPa）、2022=2400（mm）
[回读] 2021=1000  2022=2400
✓ 冒烟测试通过：模拟器可读、可写、可回读，协议解析正常
```

- 异常注入（temperature:high）在原始采样层生效，经 10 点滑窗均值后正确置位 bit0、bit7，子包序号与主包序号一致，与 PLC 程序 `Easy320_main.st` 语义吻合。
- FC16 写回 2021/2022 可回读一致，说明"写入—回读"校验有可运行的物理链路支撑。

### 3. 序号回绕缺陷复现（Q3）

```
SEQ_MOD = 65536
喂 65 536 帧(seq 1..65535 循环, 含 65535→1 回绕): gaps = 1, expected = 65537
期望: 零丢包场景 gaps 应为 0；gaps=1 说明回绕被误计为缺口
```

- 与 `E20` 实验记录完全一致（"现实现 mod 65536 → 每回绕 1 个虚假缺口"）。

### 4. 阶跃告警时延缺陷复现（Q2）

```
阶跃 25→85°C 阈值 80°C 告警: {"ms":98000,"level":"warning","source":"threshold","vote":null}
stats: {total:1, suppressed:41, voteRejected:81, rocAlarms:0, thrAlarms:1}
```

- 98 s 后最终以 `threshold` 通道告警，说明阈值通道"最终"还是成立了，但被变化率投票门控**连带压了 98 s**，违背论文"阈值通道独立成立"的声明。

### 5. 中值滤波方差削减比（论文式（8））

```
原始方差 = 0.9997
中值滤波后方差 = 0.4491
方差削减比 = 0.4492 (论文声称 0.4487)   σeff/σ = 0.6702 (论文声称 0.670)
```

- 论文式（8）的理论值正确，无需改动。

## 三、对论文"数据可靠性"结论的判定

| 论文声明 | 实测 | 判定 |
|---|---|---|
| 双包协议 31 B/62 B、压缩 77.4×（32 bit 基线） | 流量核算正确，但基线口径偏高（见 Q1） | ⚠ 口径需改 |
| 丢包率 1%～10% MAE ≤0.50 pp | `R5/E3` 实测 5%→0.550、10%→0.811，突破声明 | ⚠ 需复核 |
| 序号回绕"处理后 0 缺口" | 代码仍 mod 65536，实测 gaps=1 | ❌ 代码未修复 |
| 纯噪声误报 78.8 次/h → 0 | `E19` 同口径下 7% 试验出现误报、日均 20.16 次 | ⚠ 口径敏感 |
| 3 ℃/min 缓变提前 1 012 s | 工作点 T=90 s 时 91 s、提前约 1 012 s，与表 8 一致 | ✔ 成立 |
| 数据质量码 20 000 次随机查询一致 | `E4` 脚本未喂包，实际 3 303 次不一致 | ⚠ 测试脚本有 bug |
| 中值滤波方差削减比 0.448 7 | 蒙特卡洛 0.449 2 | ✔ 正确 |

**总结论**：平台的协议、编码、链路、告警、运维五大模块的**工程实现基本正确**，但存在**一处真实功能缺陷（Q2 阶跃时延）与一处未落地的修复（Q3 序号回绕）**；论文的**定量结论在口径上有多处需收紧**。核心贡献成立，但投稿前须按 `01` 与 `05` 的处理方案修正。
